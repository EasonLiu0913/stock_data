# 股票預測事後覆盤機制

這份文件定義「事前預測」完成後，如何在下一交易日實際行情資料到位時，產生事後覆盤、準確與不準清單、以及後續因子歸零測試。目標是讓預測系統能逐步驗證哪些判斷要素有效，而不是只是不斷疊加更多因子。

範例：目前已有 `data_predictions/20260727/summary.json`，這批資料代表用 `2026-07-24` 的基準資料預測 `2026-07-27`。等爬蟲取得 `2026-07-27` 真實行情後，就可以對這批預測做覆盤。

## 核心目標

- 比對每檔股票的事前預測與下一交易日實際走勢。
- 不只看收盤漲跌，也要看盤中氛圍，例如開高走低、開低走高、放量下殺、縮量整理。
- 列出明顯準確與明顯不準確的股票清單。
- 對準確與不準案例產生原因標籤，找出成功原因與失敗周圍因素。
- 支援因子歸零測試、移除測試與重新組合，避免模型只會越疊越肥。

## 需要的實際行情資料

覆盤需要下一交易日的真實 OHLCV：

| 欄位 | 用途 |
|---|---|
| 前一交易日收盤價 | 計算開盤與收盤相對基準。 |
| 實際開盤價 | 判斷開高或開低。 |
| 實際最高價 | 判斷盤中上攻與震幅。 |
| 實際最低價 | 判斷盤中下殺與震幅。 |
| 實際收盤價 | 判斷最終方向。 |
| 實際成交量 | 判斷放量、縮量與氛圍強度。 |
| 5 日 / 20 日均量 | 作為成交量放大或萎縮基準。 |

以 `20260727` 預測批次為例，覆盤會比對：

```text
data_predictions/20260727/summary.json
data_fubon/fubon_20260727_sma.json
```

## 實際走勢標籤

第一版用規則產生每檔股票的 `actual_pattern_tags`：

| 標籤 | 初步判斷方式 |
|---|---|
| 開高走高 | 開盤高於前收，且收盤高於開盤。 |
| 開高走低 | 開盤高於前收，但收盤低於開盤。 |
| 開低走高 | 開盤低於前收，但收盤高於開盤。 |
| 開低走低 | 開盤低於前收，且收盤低於開盤。 |
| 放量上攻 | 成交量高於均量門檻，且收盤偏強。 |
| 放量下殺 | 成交量高於均量門檻，且收盤偏弱。 |
| 縮量整理 | 成交量低於均量門檻，且漲跌幅與震幅都不大。 |
| 長上影賣壓 | 盤中高點明顯高於收盤。 |
| 長下影承接 | 盤中低點明顯低於收盤。 |

實作時應保留原始數值，標籤只是方便 dashboard 與覆盤摘要閱讀。

## 實際氛圍分數

不要只用「收漲或收跌」判斷準不準。建議額外產生 `actual_mood_score`：

| 分數方向 | 可能來源 |
|---|---|
| 偏多加分 | 收盤上漲、開低走高、放量上攻、長下影承接。 |
| 偏空扣分 | 收盤下跌、開高走低、放量下殺、長上影賣壓。 |
| 中性 | 小漲小跌、縮量、低震幅。 |

可再轉成 `actual_mood_label`：

- 強多
- 偏多
- 中性
- 偏空
- 強空

## 準確度判斷

覆盤應產生兩種準確度：

| 欄位 | 說明 |
|---|---|
| `direction_accuracy` | 預測方向和實際收盤方向是否一致。 |
| `mood_accuracy` | 預測氛圍和實際盤中氛圍是否一致。 |

最後再合成 `prediction_match_label`：

- 明顯準確
- 大致準確
- 中性難判
- 大致不準
- 明顯不準

範例：

| 事前預測 | 實際走勢 | 判斷 |
|---|---|---|
| 偏多 | 開低走高、收漲、放量 | 明顯準確 |
| 偏多 | 開高走低、收黑、放量 | 明顯不準 |
| 偏空 | 開低走低、收跌、放量 | 明顯準確 |
| 偏空 | 開低走高、收紅、放量 | 明顯不準 |
| 中性 | 小幅震盪、縮量 | 大致準確 |

## 建議產出檔案

第一版可以產生三個檔案：

```text
data_predictions/YYYYMMDD/replay.json
data_predictions/YYYYMMDD/replay-summary.json
data_predictions/YYYYMMDD/replay-mistakes.json
```

### `replay.json`

逐檔股票覆盤資料：

- 原始預測方向、分數、風險。
- 實際 OHLCV。
- 實際開盤報酬、收盤報酬、盤中報酬、震幅、量比。
- 實際走勢標籤。
- 準確度判斷。
- 原因標籤。

### `replay-summary.json`

Dashboard 使用的摘要：

- 預測檔數。
- 已驗證檔數。
- 明顯準確數量。
- 明顯不準數量。
- 偏多命中率。
- 偏空命中率。
- 放量情境命中率。
- 開高走低誤判數。
- 開低走高漏判數。
- 產業命中率。
- 策略分類命中率。
- 概念股清單命中率。

### `replay-mistakes.json`

明顯不準案例集中分析：

- 股票清單。
- 原預測。
- 實際型態。
- 可能誤判原因。
- 周圍影響因素。
- 相關產業、策略標籤、概念股分類。

## Dashboard 覆盤區塊

Dashboard 可以新增「事後覆盤」區塊：

- 如果 `replay-summary.json` 不存在，顯示「等待實際行情資料」。
- 如果存在，顯示覆盤 KPI。
- 列出「明顯準確」與「明顯不準」清單。
- 支援依產業、策略分類、概念股清單觀察命中率。

建議第一版先做：

- 明顯準確 Top 30。
- 明顯不準 Top 30。
- 誤判最集中的產業。
- 誤判最集中的概念股。
- 命中率最高的策略標籤。
- 命中率最低的策略標籤。

## 原因標籤

成功原因標籤範例：

- 技術轉強後續強。
- 放量配合方向。
- 產業同步偏多。
- 籌碼同步偏多。
- 大盤環境支持。
- 相對強勢有效。
- 低風險高完整度樣本命中。

失敗原因標籤範例：

- 開高出貨。
- 放量反殺。
- 量能不足。
- 產業拖累。
- 大盤或期貨反向。
- 高風險波動蓋過方向訊號。
- 籌碼與技術矛盾。
- 預測時資料缺漏。
- 前一日過熱導致隔日反轉。
- 個股新聞或事件影響。

## 因子實驗與歸零測試

覆盤系統不應只把更多因子加進模型。需要把因子拆成可開關的 registry：

```text
price_momentum
volume_expansion
sma_reclaim
macd_turn
kd_turn
chip_bias
relative_strength_7d
industry_strength
market_risk
news_confidence
data_completeness_penalty
concept_strength
```

每次覆盤後可以跑不同組合：

| 實驗 | 目的 |
|---|---|
| 全因子 | 目前完整模型表現。 |
| 歸零基準 | 不使用加權因子，只看最基礎方向。 |
| 只用技術 | 驗證技術面獨立效果。 |
| 只用籌碼 | 驗證籌碼面獨立效果。 |
| 只用市場風險 | 驗證大盤與新聞風險效果。 |
| 技術 + 量能 | 驗證價量組合。 |
| 技術 + 量能 + 產業 | 驗證產業同步是否改善。 |
| 全因子移除單一因子 | 做 ablation test，檢查某因子是否真的有用。 |

目標是找出：

- 哪些因子單獨有效。
- 哪些因子加入後改善明顯。
- 哪些因子移除後反而更好。
- 哪些因子只在特定環境有效。
- 哪些因子造成模型變肥但沒有提升。

建議後續產出：

```text
data_predictions/YYYYMMDD/factor-experiments.json
```

## 建議實作順序

1. 新增 `scripts/generate_prediction_replay.js`。
2. 先讀 `summary.json` 與實際行情檔，產生逐檔 `replay.json`。
3. 定義實際走勢標籤與準確度規則。
4. 產生 `replay-summary.json` 與 `replay-mistakes.json`。
5. 在 dashboard 預留「事後覆盤」區塊。
6. 等 `2026-07-27` 真實行情抓到後，執行：

```bash
node scripts/generate_prediction_replay.js --date 20260727
```

或使用 npm script：

```bash
npm run replay:prediction -- --date 20260727
```

在實際行情尚未到位前，可用 `--dry-run` 搭配既有行情日測試流程是否正常，但這不代表真實覆盤結果：

```bash
node scripts/generate_prediction_replay.js --date 20260727 --actual-date 20260724 --dry-run
```

7. 第一版先觀察明顯準確與明顯不準清單，不急著調整預測模型。
8. 累積多個交易日後，再開始做因子歸零測試與重新組合。

## 20260727 第一版覆盤流程

當 `data_fubon/fubon_20260727_sma.json` 出現後：

1. 確認 `data_predictions/20260727/summary.json` 存在。
2. 執行覆盤腳本。
3. 產生 `replay.json`、`replay-summary.json`、`replay-mistakes.json`。
4. Dashboard 顯示覆盤區塊。
5. 人工檢查明顯準確與明顯不準清單是否合理。
6. 再決定是否進入因子實驗。
