## Frozen decisions / constraints

1. Yahoo Finance futures remain the current fast oil-market reference:
   - WTI: `CL=F`
   - Brent: `BZ=F`
2. EIA spot data remains a separate slower official spot benchmark and must not be overwritten or relabeled as Yahoo futures.
3. Market Environment v4 oil context remains shadow-only:
   - `oil_market.scoring_effect = "none_shadow_context"`
   - no formal market-environment score adjustment;
   - no prediction-direction adjustment;
   - no strategy gate;
   - no stock inclusion/exclusion rule.
4. Preserve the current deterministic oil fields and semantics:
   - WTI / Brent `change_1d_pct`
   - WTI / Brent `return_5d_pct`
   - WTI / Brent `return_20d_pct`
   - `oil_trend`
   - `oil_shock`
5. Current deterministic thresholds are observational only. Do not tune them in this round.
6. Market environment remains context rather than a fixed-strategy gate, per repository philosophy.
7. Do not add another oil crawler or duplicate Yahoo requests.
8. Do not duplicate the oil classification logic in the frontend. UI must consume the canonical `market_environment.json` fields generated by the existing backend logic.
9. Missing/null oil data must render as unavailable/NA, never as a false zero.
10. Preserve existing Market Environment banner behavior, rebound-readiness UI, prediction dashboard behavior, and freshness logic.
11. Do not build a new generic framework for this first consumer rollout.

## Known problems / rejected approaches

### Rejected: separate Yahoo oil crawler

Not needed. `crawl-external-market-indicators.yml` already fetches WTI/Brent alongside external indicators.

### Rejected: use EIA weekly spot as the fast daily signal

EIA remains useful as an official spot benchmark but its publication cadence is too slow for the current daily market-risk use case.

### Rejected: directly add oil shock to formal Market Environment score

There is not yet enough historical evidence that a fixed oil threshold has stable broad-market or sector effects across regimes.

### Rejected: duplicate oil classification in frontend code

Frontend should present the canonical backend `oil_market` classification and metrics, not independently reinterpret thresholds.

### Deferred: AI prompt integration

The product intent is to let the existing AI market analysis distinguish at least:

- short-term oil shock;
- medium-term oil/inflation pressure;
- stable/falling oil;
- whether market-price reaction confirms or contradicts the news narrative.

However, the exact canonical AI consumer path is not yet verified. This active round must locate and document it before implementation is authorized in a later round.
