# Date-to-Video V1 — Workflow-trust-first amendment proposal v1

Owner direction (2026-10-21): reuse already date-checked outputs from existing daily workflows; do not require a second independent raw HTTP acquisition/certification for every daily video input. This is a proposed versioned change to the prior A contract, NOT a retroactive PASS of the frozen original Prompt B, a production permission, or a claim that missing data exists.

## New default acceptance
1. Prefer existing same-date repository workflow outputs and their persisted provenance/run metadata. A successful workflow alone is insufficient if its file is missing, stale, malformed, or from the wrong date.
2. Lightweight per-date checks: expected file and workflow identity, embedded target trading date, parseable schema, required columns, numeric units, nonempty/valid figures, SHA-256 or stable artifact identity, and consistency across sources. Reuse already validated BFI82U archive without fetching again.
3. If an existing workflow produces a dated derived FMTQIK chart or MI_INDEX stock-column aggregate, accept it as workflow-derived evidence for its explicitly declared scope after these checks; do not mislabel it as independently certified original HTTP. Distinguish official aggregate 股票 column from ordinary-common-stock universe; do not infer individual security identity.
4. BFIAMU is industry turnover context with overlapping categories, not institutional capital flow. If a dated BFIAMU file is absent, report its actual mandatory/optional consumer impact; do not invent an archive or copy a prior date. Resolve mandatory coverage by existing authorized workflow recovery, not unconditional raw recapture.
5. Deep review/recovery only for missing file, date/schema/unit/scope mismatch, inconsistent figures, changed upstream workflow contract, or suspicious values. Never silently use another date, suppress a mandatory editorial claim, or fabricate a source.
6. Separate statuses: WORKFLOW_OUTPUT_VALIDATED_FOR_RESEARCH_USE versus ORIGINAL_HTTP_INDEPENDENTLY_CERTIFIED. The former can feed the date-scoped research Master within reviewed scope; the latter is not required universally. Master/editorial/media acceptance remains independent. All publication/production/cron/Pages/YouTube/release flags remain false until separately authorized.
